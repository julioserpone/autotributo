# 12 — Plan: F2-08 Persistencia idempotente de comprobantes

> Documento de planificación de la tarea **F2-08** de `docs/02-implementation-plan.md`.
> El avance real se registra en `docs/09-progress.md`.

**Fecha:** 2026-10-27 · **Rama:** `feat/F2-08-persistencia-idempotente`

## 1. Punto de partida

`ParseSriRun` (F2-07) ya produce `SriPeriodBatch` con las claves de acceso
válidas, y `PackageSriInvoiceParser` (F2-06) convierte un XML en
`SriInvoiceData`. Lo que falta es el puente entre ambos: consultar el SRI por
clave, guardar el comprobante y dejar el run en un estado terminal honesto.

```text
reconcile  → parsing → [ParseSriRun] → claves por período/tipo
                                          │
                                          ├─ SriAuthorizationGateway.query(clave) → XML
                                          ├─ SriInvoiceParser.parse(XML) → SriInvoiceData
                                          └─ PersistSriInvoice → invoices + hijos   ← F2-08
```

Nada de esto existe todavía: no hay tabla `invoices` ni forma de reejecutar un
run sin duplicar. Ese es el objetivo.

## 3. Diseño

### 3.1 Esquema

Sigue `docs/03-data-model.md` §6 al pie de la letra: montos en centavos
(`bigint`), `tenant_id` en todas las tablas de negocio, `public_id` ULID,
estados `varchar` + enum PHP, sin `ENUM` nativo de Postgres.

Invariante de idempotencia: `unique(tenant_id, company_id, access_key)`.

`invoice_items` y `invoice_taxes` se reemplazan cuando cambia la huella del
XML (misma clave, `xml_sha256` distinto): un comprobante autorizado no cambia,
pero el SRI puede republicar un XML corregido, y el modelo no debe acumular
duplicados.

### 3.2 Idempotencia

| Caso | Resultado |
|---|---|
| Clave nueva | `created`, se insertan hijos |
| Clave existente con mismo `xml_sha256` | `skipped`, no se tocan las filas |
| Clave existente con `xml_sha256` distinto | `updated`, se reemplazan los hijos |
| XML con totales inconsistentes | Se persiste igual y `totalsMismatch` queda en el DTO para F3 |

`updated_or_created_at`, `sync_run_id` y `first_seen_at` no se pisan en un
`skipped`: la fila guarda el primer run que la vio y el último que la tocó.

### 3.3 Fallos parciales

Un XML que no se puede consultar o interpretar **no tumba el run**: se cuenta
en `failed`, se registra en `sri_sync_run_files.error_message` (sin claves de
acceso completas ni contenido) y el resto continúa. Regla de estado:

| Resultado | Estado del run |
|---|---|
| Todos los documentos importados o saltados | `completed` |
| Alguno falló y otros se guardaron | `partial` |
| Ninguno se pudo guardar | `failed` con `error_code=import_failed` |

### 3.4 Acceso al SRI

`ImportSriRun` usa el puerto `SriAuthorizationGateway` con
`SRI_AUTHORIZATION_DRIVER=fake` en tests. El fake devuelve XML desde fixtures y
permite simular `not_found`, `rejected`, error de transporte y claves
autorizadas por lista.

> El gateway actual se consulta por clave sin credenciales del portal; el
> certificado/credencial del contribuyente sigue pendiente de F1-06 y no se
> necesita para la autorización pública de comprobantes.

## 4. Pruebas obligatorias

| Tipo | Caso |
|---|---|
| Unit | `SriInvoiceData` → armado de filas: centavos exactos, `issuer/receiver`, `direction=received`, `source=sri_robot` |
| Unit | Invariantes: `tax = sum(taxes)`, `total = subtotal − descuento + impuestos`, `items.subtotal` suma |
| Feature | Importar un run con 3 documentos: 3 `invoices`, 0 duplicados |
| Feature | Reimportar el mismo run: `assertDatabaseCount` igual y todos `skipped` |
| Feature | Mismo `access_key` con XML distinto: reemplaza hijos sin duplicar `invoice_items` |
| Feature | Un XML corrupto → run `partial`, el archivo queda con motivo, los otros importados |
| Feature | Todos fallan → run `failed`, `error_code=import_failed` |
| Feature | Aislamiento: la misma clave en dos empresas del tenant no colisiona |
| Feature | Aislamiento: la misma clave en dos tenants distintas crea dos filas |
| Feature | Retención (07): `retention_lines` con código, base y valor |
| Feature | NC/ND: `invoice_relations` no se crea en F2-08; la clave ajustada solo se persiste en `raw` |
| Arch | `App\Domain\Sri` no importa SOAP, AWS ni el paquete directamente (solo a través del puerto) |

## 6. Riesgos

| Riesgo | Mitigación |
|---|---|
| Lentitud: una consulta SOAP por clave (hasta ~44 por archivo) | F2-08 no paraleliza a propósito: primero se mide. F2-10 añade lotes y backoff |
| El SRI responde `PPR` (en proceso) para una clave | Se cuenta como `failed` recuperable con `error_code=pending_authorization`; F2-10 reintenta |
| Escritura a medias por un XML con ítems que no cuadran | La persistencia va en una transacción por comprobante, no por run |
| Credenciales en logs | Solo se registra `run_id`, tipo y conteos; nunca la clave completa ni el XML |
